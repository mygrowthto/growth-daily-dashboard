# 增长日报台 · 用户运营数据工作台

> **免责声明**：本项目全部代码、数据、文案与图表均已脱敏处理，仅使用 3 天样例数据演示分析方法；不含公司内部资料、真实账号信息、用户聊天记录或可识别个人信息，不代表真实企业结论。

基于实习期间的用户运营日报体系构建的零依赖数据工作台：以原始计数为唯一数据源，由代码统一重算指标，并把口径差异、异常与数据边界直接呈现在页面上。

- https://growth-daily-dashboard.app.workbuddy.host/?sharecode=DASKOPVRPM （备用）

源码仓库：https://github.com/mygrowthto/growth-daily-dashboard

## 功能

- 按日切换的 KPI：播放、触达、回复率、微信转化率、环比与异常预警；
- 首日指数 100 的双折线趋势图，解决十万级播放与百级触达无法同图比较；
- 四段转化漏斗（播放 → 触达 → 回复 → 微信）及相邻环节转化率；
- 话术版本对照（A/B 测试设计 · 观察性复盘）与样本、限制说明；
- 日报明细表：原始百分比与公式重算值并列，差异有视觉标记；
- 指标口径、数据限制与下一步验证方向。

## 项目背景

实习日报包含播放、粉丝、评论、私信触达、回复与微信转化等指标，原表存在手工填写的百分比与不一致口径。例如 8 月 1 日原表记录微信转化率 4.3%，按微信数 25 ÷ 触达数 397 计算应为 6.3%。本工作台让每个数字可追溯：页面只读取原始计数，所有比例由计算函数重算，并对差异给出明确标记，而不是沿用原表数值。

## 设计决策

### 指标口径先于页面

| 指标 | 定义 |
|---|---|
| 回复率 | 回复数 ÷ 触达数 |
| 微信转化率 | （主动微信 + 被动微信）÷ 触达数 |
| 播放指数 | 当日播放 ÷ 首日播放 × 100 |
| 触达指数 | 当日触达 ÷ 首日触达 × 100 |

`safeRatio` 统一处理分母为 0、非数值等边界，返回 `null` 而不是伪造的 0。页面与测试基于同一套公式，避免各处硬编码百分比。

### 测试先行

24 个自动化测试（`node:test`）覆盖指标公式、数据完整性、SVG 图表几何与静态服务器行为。先固化期望值再实现计算函数，保证口径变更能被测试捕获；空数据、零基线与重复日期均有回归用例。

### 计算与渲染分离

`src/metrics.js` 只做指标计算，`src/charts.js` 只接收计算结果并返回 SVG / 漏斗 HTML，`src/app.js` 负责读取数据与页面更新。图表几何可独立测试，日期切换不需要重写公式，后续替换视图层也不影响计算逻辑。

### 可视化取舍

播放为十万级、触达为百级，共用同一根 y 轴会淹没后者，因此趋势图以首日 = 100 的指数对比变化方向，同时保留绝对值明细表。指数仅用于比较方向，不替代绝对量级。

### 零依赖静态部署

原生 HTML / CSS / ES Modules + 原生 SVG，无框架、无第三方库、无在线 CDN；`scripts/serve.mjs` 用 Node 内置模块提供本地服务。所有资源使用 `./` 相对路径，可直接托管在 GitHub Pages 子路径下。

## 项目结构

```text
growth-dashboard/
├─ index.html                 # 页面结构与章节
├─ assets/styles.css          # 视觉系统与响应式布局
├─ data/daily-data.json       # 3 天原始数据与口径说明
├─ src/metrics.js             # 指标计算：比例、指数、漏斗、预警
├─ src/charts.js              # 原生 SVG 图表
├─ src/app.js                 # 数据读取、渲染与日期切换
├─ scripts/serve.mjs          # 零依赖静态服务器
├─ tests/                     # 指标、数据、图表、服务器测试
└─ docs/                      # 设计说明与实现说明
```


```powershell

```

## 数据边界与局限

- 数据来源：实习期间自建的用户运营数据日报体系（内部资料，已脱敏；本项目不含原始文档链接或任何公司内部资料）。
- 仅覆盖 2026 年 8 月 1 日至 3 日，只能提示方向，不能证明长期趋势。
- 微信转化数与回复数在样例中相同，可能存在口径重叠，需向原团队核实。
- 话术按用户互动行为分层，两版记录按日期分组，未做随机分流、样本量计算与预设观察周期，因此称为「A/B 测试设计 · 观察性复盘」，不声称因果或显著提升。
- 下一步：核实微信口径，补充 7–14 天并按渠道 / 内容主题拆分，再设计层内随机的规范实验。
