# 用户运营数据日报工作台 · 设计说明

## 1. 问题与目标

实习日报体系包含播放、粉丝、评论、触达、回复、微信转化等指标，原表存在手工百分比与口径不一致。本作品把这套日报转成可浏览、可解释的网页工作台，目标是让每个指标可追溯、异常可定位、边界可说明。

## 2. 原始材料

内部日报（已脱敏）包含：

- 四类报表：个人日报、多日趋势、漏斗效率、多渠道日报；
- 三层指标：流量层、触达层、转化层；
- 8 月 1–3 日的汇总与漏斗数据；
- Excel 用法：多 Sheet、条件格式、数据验证、公式与图表；
- 两个洞察案例：播放增长但触达未同步、话术版本变化后回复率变化；
- 体系价值：异常可追溯、复盘有依据、日报转周报、组间对比。

## 3. 方案比较

| 方案 | 优点 | 缺点 | 复杂度 |
|---|---|---|---|
| A. 无框架静态工作台 | 无后端、零依赖、易部署、文件结构透明 | 复杂交互不如组件框架 | 低 |
| B. React + Vite | 组件化、扩展性好 | 需构建工具与更多依赖 | 中 |
| C. Python Streamlit | 分析代码短 | 前端定制与视觉完成度有限 | 低到中 |

选用方案 A：把重点放在指标口径、数据计算与业务解释，而非框架搭建。

技术选择：原生 HTML / CSS / ES Modules；数据存于 `data/daily-data.json`；图表用语义化 HTML 与原生 SVG，不依赖在线 CDN；测试用 Node.js 内置 `node:test`；本地静态服务器，成品可发布到 GitHub Pages。

## 4. 页面结构

- 总览：日期、触达、回复率、微信转化率四张指标卡；播放与触达趋势对比；异常提示；样本范围提示。
- 转化漏斗：播放 → 触达 → 回复 → 微信，逐步给出数值与相邻环节转化率，并显示公式。
- 话术复盘：A / B 两版回复率对比，标注样本量与「非随机分组」限制。
- 日报明细：3 天数据、按日切换、原始展示值与自动重算值并列。
- 方法与边界：指标字典、数据来源、已知差异、因果限制。

## 5. 视觉方向

- 工作台而非营销落地页，信息密度适中，表格与图表优先。
- 黑白灰为主，细网格底纹、衬线标题、1px 边框与硬阴影构成编辑设计风格；折线以黑实线 / 灰虚线 + 空心点区分。
- 桌面双栏、移动端单栏；数字使用稳定宽度，避免切换筛选时跳动。

## 6. 数据规则

- 回复率 = 回复数 ÷ 触达数；微信转化率 = 微信转化数 ÷ 触达数；播放到触达放大比 = 触达数 ÷ 播放量。
- 所有百分比保留一位小数，由分子分母统一计算，不硬编码报表数值。
- 8 月 1 日来源表显示 4.3%，按 25 ÷ 397 计算为 6.3%；界面并列展示并标注「已按公式重算」。
- 话术记录按日期分组、无随机分流，统一称为「版本对比 / A/B 测试设计 · 观察性复盘」，不声称因果。

## 7. 范围外

登录、权限、云端数据库、多用户协作、真实企业数据导入、自动抓取平台数据、统计显著性检验、支付与后台管理。

## 8. 验收标准

- 桌面 1440×900 与手机 390×844 下无文字溢出或重叠。
- 所有百分比由代码计算，测试覆盖主要公式与边界。
- 至少一条异常可被自动识别并解释。
- 话术对比明确标注样本与因果限制。
- 静态服务与数据接口返回正确状态码。

## 9. 风险

- 样例数据仅 3 天，趋势代表性有限，页面需明确说明。
- 部分原始指标口径可能不一致，不能直接复制结论。
- 3 天样本不足以做显著性检验。
- 涉及实习内容，须隐藏公司、医生账号、用户信息与内部截图。
